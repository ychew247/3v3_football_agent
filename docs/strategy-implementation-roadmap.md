# 3V3 策略渐进式实现规格

## 目标与实施方式

本路线图把当前提出的进攻、防守、守门、争球、避障、角色和定位球方案拆成可独立运行的模块。每完成一个模块，都必须在 Booster Studio 中录到与基线相比的可见变化；不能用“计划实现”代替已完成成果。

策略不假设机器人拥有真实持球状态，也不假设能够获得真实球速、旋转、碰撞力或未来物理轨迹。所有决策只使用 `context` 中当帧的球、队友、对手、裁判和场地信息，以及 `store` 中由这些公开快照保存的历史信息。

## 总体架构

```text
main.py
  阶段检查 -> 合规保护 -> 全队角色分配 -> 调用球员高层动作

player.py
  守门、逼抢、补位、接应、踢球接近、踢向目标等单机器人动作

utils/
  纯几何：线路是否被封堵、目标点、短期落点估计、场内钳制

param.py
  所有距离、力度、评分权重、迟滞余量和速度限制
```

球相关动作始终遵循同一物理流程：

```text
选择目标和力度 -> 走到球后方/靠近球 -> kick() 持续踢球任务
-> 球移动 -> release_kick()/追球 -> 下一帧重新判断
```

`shoot`、`pass`、`advance` 和 `clear` 是不同的**决策模式**，不是新的物理控球能力。`advance` 只能描述为“小力短踢后继续追球”，不能描述为真实持球盘带。

## 每个模块的通用完成标准

1. 只修改 `src/main.py`、`src/player.py`、`src/param.py` 或 `src/utils/`；不修改 `src/framework/`。
2. 新数值先放入 `param.py`，不在策略文件散落魔法数字。
3. `ball`、`game`、`pose` 均有空值保护；`STOPPED` 时不踢球且全员停车。
4. 每帧每个球员只执行一个高层动作；角色和球动作均使用 `store` 迟滞，避免频繁切换。
5. 完成后在 Studio 中至少录制一段“基线 vs 修改后”的相同场景片段，并保留截图、比分、摔倒和罚下信息。
6. 修改涉及运动、踢球、开球或定位球后，再部署前必须做完整规则检查。

## M0：基线记录与可视化准备

**目的：** 先建立可信对照，后续每项改动都有证据。

**改动范围：** 不改策略逻辑；使用现有 `phase`、队员 `action`、球位置、距离和踢球目标可视化。

**执行任务：**

- 在相同对手和相近设置下录制基线片段：守门、对方带球推进、我方进攻、定位球各一段。
- 记录每场的比分、失球方式、摔倒、罚下和明显卡住情况。
- 建立一张实验记录表：日期、代码版本、只改了什么、场次、结果、视频文件名。

**完成证据：** 一组基线视频/截图和一张可追溯的实验记录表。

## M1：规则安全与空值稳健性（先做）

### M1.1 对方定位球退开等待

**问题：** 当前 `_act_opp_set_play()` 直接复用正常抢球，可能在对方触球前靠近或触球。

**改动范围：** `main.py` 的 `_act_opp_set_play()`；必要的等待距离参数放入 `param.py`。

**逻辑：**

1. 当 `Phase.OPP_SET_PLAY` 时，所有可行动球员选择距球大于规则距离、且大于 3 m 的等待点。
2. 守门员保持防守位置；其余球员沿球到己方球门方向后退并横向错开。
3. 只在官方 `set_play` 清空、阶段变为 `NORMAL` 后恢复争球；不用本地计时猜测球权是否开放。

**完成证据：** 对方定位球时全队明显退开、未提前触球的录像和裁判日志。

### M1.2 开球合规流程

**问题：** 当前我方开球直接朝球门踢，可能造成无效进球；对方开球等待也必须保持中圈外和安全距离。

**改动范围：** `main.py` 的开球分支、`param.py` 的开球推球距离/方向参数。

**逻辑：**

1. 我方开球先将球斜向前轻推到合规距离外，或传给第二名机器人；不在限制条件下直接射门。
2. 对方开球时，非守门员在中圈外和球的规则安全距离外等待。
3. 所有判断以官方 `context.game` 阶段为准。

**完成证据：** 开球站位和首脚处理的录像；无开球位置或无效进球问题。

### M1.3 球丢失时安全降级

**问题：** 球可能短暂为 `None`；支援和新模块不能继续读取球坐标。

**改动范围：** `player.py` 的 `support()` 及新增球相关方法。

**逻辑：** 球未知时，攻击者停车或回到安全等待；守门员保持守门；所有球相关计算提前返回。

**完成证据：** 数据短暂丢失时控制循环不报错、不出现危险移动。

## M2：守门员横向跟球（优先视频展示）

**目的：** 让守门员从固定站在球门中央，变为保守地覆盖球当前的横向射门线路。

**改动范围：** `player.py` 的 `guard()`；`param.py` 增加守门横移范围、平滑系数和门线安全余量。

**逻辑：**

1. 以己方门线附近的固定 `x` 作为守门纵向位置。
2. 根据球当前 `y` 计算目标 `y`，再钳制在球门宽度和安全余量内。
3. 只在己方半场或球具有威胁时更积极横移；球未知时回中。
4. 守门员不冲向球、不越过安全纵向边界；目标位置变化使用平滑和迟滞。

**不做：** 不承诺预测对手下一脚射门，也不尝试自动扑救动作。

**完成证据：** 同一横向带球场景中，修改后守门员随球横移而不离开门前的前后对比视频。

---

## M3：基础防守协同——逼抢、补位、守门

**目的：** 防止三名机器人同时围球，形成可见的 1-1-1 防守结构。

**改动范围：** `main.py` 的 `_act_normal()` 和角色选择；`player.py` 新增或复用 `press`、`cover` 站位动作；`param.py` 增加角色切换余量和补位距离。

**逻辑：**

1. 从可行动球员中选一人 `press`：通常是到球时间最短、且不会放空己方球门的人。
2. 选一人 `cover`：站在球与己方球门之间偏侧的位置，保持防守深度，不直接冲球。
3. 剩余一人 `guard`：执行 M2 的守门动作。
4. 使用 `store` 保存 `presser_id`、`cover_id`、`guard_id`；只有原角色不可行动或候选者明显更优时才切换。
5. “盯防对象”定义为当前最可能接球或最威胁球门的对手，不声称系统能识别真实持球人。

**不做：** M3 不实现双人包夹。双人包夹必须等覆盖角色稳定后再单独实验。

**完成证据：** 对方推进时的截图：一人逼抢、一人回收补位、一人守门；与基线三人围球场景对比。

---

## M4：射门目标选择

**目的：** 从“始终踢向球门中心”升级为“从有限候选目标点中选择当前较空的一点”。

**改动范围：** `player.py` 的踢球规划；必要的线段几何放入 `utils/geom.py`；阈值放入 `param.py`。

**新增纯几何工具：**

- 点到线段的最短距离。
- 球到目标点线路的最近对手距离。
- 球门候选点生成：左、中、右三个场内目标点。

**逻辑：**

1. 在左、中、右球门候选点中计算射门线路的对手净空和推进方向。
2. 排除明显被对手或守门员当前站位封堵的线路。
3. 在剩余候选中选择净空较大、角度较好的目标；没有足够好的线路时交给后续 M5 决策。
4. 保留现有踢球迟滞，避免目标点每帧左右跳动。

**不做：** 不预测球完整飞行轨迹，也不保证躲过守门员扑救。

**完成证据：** 现有紫色踢球目标标记从始终居中，变为在不同对手站位下选择左/右空挡的截图和录像。

## M5：进攻模式选择——Shoot、Advance、Clear

**目的：** 先完成不依赖接球队员的三种球动作，替代当前“任何位置都射门”。

**改动范围：** `player.py` 新增共享 `kick_to(target, power)` 和 `choose_attack_action()`，或等价地扩展 `attack()`；团队层阈值可由 `main.py` 决定。所有参数放入 `param.py`。

**共享原语：**

```text
kick_to(target, power)
  计算 ball -> target 的场地角度
  走到球后方
  调用持续 kick(direction, power)
  下一帧根据最新球位置继续或释放踢球
```

**决策优先级：**

1. `shoot`：M4 给出有足够净空的射门线路。
2. `advance`：没有好射门，且球前方短距离空位的线路安全；低力度短踢后追球。
3. `clear`：己方危险区域受压、没有安全射门或推进时，向前方边路或空区较大力踢出。

**状态估计：** 不保存“球属于我方”的事实。只用球距、最近球员、对手压迫和球是否仍在预期区域估计控制情况；失去控制时立即重新选择。

**完成证据：** 三段独立场景录像：空挡射门、短踢推进、后场安全解围。场上 `action` 标签必须显示当前模式。

## M6：传球与接应（在 M5 稳定后）

**目的：** 实现有限、可解释的定向传球，而不是承诺准确传球或真实控球。

**改动范围：** `main.py` 决定接应者和接应点；`player.py` 的 `pass_to(target)` 使用 M5 的 `kick_to()`；`utils/geom.py` 复用线路净空。

**逻辑：**

1. 先为非攻击者安排前方或侧前方接应点，避免所有人停在球附近。
2. 对每名候选队友评估：是否更安全/更向前、传球线是否远离对手、接应点是否在场内。
3. 只有最佳候选显著优于 `advance` 时才传球；否则保持 M5 的推进或解围。
4. 接球队员不被视为必然接到球；传球后全队依据新的球位置重新分配角色。

**不做：** 不做长距离、穿越多人或基于精确未来轨迹的传球。

**完成证据：** 至少一段可重复场景：攻击者向预先移动的接应者定向踢球，接应者继续追球或获得下一次攻击机会。

## M7：短期球运动估计与主动争球

**目的：** 改善松散球的抢点，但不伪造精确物理预测能力。

**改动范围：** `main.py` 的 `store` 维护球位置历史；`utils/geom.py` 或小型新工具模块实现估计；`param.py` 定义样本数、最大预测时长和重置阈值。

**逻辑：**

1. 保存最近 2–4 帧可见球位置和时间，估计短期速度方向。
2. 只预测很短时间范围的潜在落点，用于选择抢球者的截击站位。
3. 球静止、数据缺失、速度突变、碰撞或新踢球后立即重置估计，回退到当前球位置。
4. 仅在 `NORMAL` 阶段使用；不以预测取代对开球/定位球官方阶段的判断。

**完成证据：** 滚动球场景中，修改后抢球者移动到球前方的合理截击点，而不是一直追向旧球位。

---

## M8：移动、避障和稳定性调参

**目的：** 在不牺牲抢球响应的前提下减少碰撞、摔倒和卡住。

**改动范围：** `param.py`、`player.py` 的 `walk_to()` 使用方式，以及必要的 `utils/obstacles.py` / `utils/path_planner.py`。

**逻辑：**

1. 区分动作：站位、补位、接应启用较强机器人避障；直接逼抢可使用较弱避障，但仍保留安全速度限制。
2. 先在 `param.py` 小幅调整速度、转向增益、障碍半径和安全余量；不要先重写 A*。
3. 拥挤区域或接近目标时降速；无路径时安全回退到局部避障或停车。
4. 每次只调一组参数，比较摔倒次数、到球时间和路径长度。

**完成证据：** 同一拥挤场景中，碰撞/摔倒减少，且没有明显变慢或绕远。

---

## M9：我方定位球战术

**目的：** 在合规前提下，为角球、球门球和界外球建立最小可用的发球—接应—覆盖流程。

**改动范围：** `main.py` 的 `_act_our_set_play()`；M5/M6 的踢球和接应模块；`param.py` 中的定位球参数。

**实施顺序：**

1. **界外球：** 近处发球者 + 一个安全接应点 + 一个后场覆盖点。
2. **球门球：** 守门员或安全发球者选择短传接应或前方边路解围。
3. **角球：** 发球者向预设接应区域踢球，另一名队员保持防守覆盖。

**硬约束：**

- 对方重开期间所有人保持规则距离，且不提前触球。
- 界外球、球门球和角球的第一脚不朝己方球门。
- 每一类定位球必须让全部可行动球员都有明确动作。

**完成证据：** 每种已完成定位球至少一段录像；未完成的种类在材料中明确标为下一阶段。

---

## M10：稳定性验证与展示材料

**目的：** 证明改动是阶段性成果，而不是偶然的一场好比赛。

**测试设计：**

1. 每次仅合入一个里程碑或一小组紧密相关改动。
2. 对相同对手、相同场景运行多场；记录比分、失球方式、罚下、摔倒、卡住和动作触发次数。
3. 为每个模块准备一张“基线 vs 修改后”的对比图或 8–15 秒视频。
4. 若结果变差，保留实验记录并回退该模块，不把它写为已提升。

**推荐展示顺序：**

```text
M0 基线问题
-> M1 合规与安全
-> M2 守门横移
-> M3 逼抢/补位/守门结构
-> M4 射门目标选择
-> M5 三种基础进攻模式
-> 后续：M6 传球、M7 预测、M9 定位球
```

## 当前阶段建议

若目标是先形成可信的阶段性展示，优先完成并录制 M1、M2、M3 和 M4。M5 可作为下一项已开始的进攻原型；M6–M9 应如实描述为后续迭代，不应在未验证前称为已完成。
